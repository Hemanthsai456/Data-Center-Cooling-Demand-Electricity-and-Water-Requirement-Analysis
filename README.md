## The Problem

Data centers consume large amounts of electricity, almost all of which is ultimately converted into heat that has to be removed by cooling systems. Estimating cooling and water demand accurately matters for controlling both energy and water costs — but it's usually reactive rather than predicted ahead of time.

This project analyzes real data-center operational telemetry (workload, power, temperature, fan speed) to quantify how workload and power translate into heat, cooling-water flow, and evaporative water demand — and is being extended into a predictive model that estimates these from operating conditions directly.

## Objective

Build a predictive analytics pipeline that:
1. Analyzes data-center operational conditions (CPU load, power, temperature, network, VM count)
2. Derives physics-based estimates of heat load and water requirements
3. Studies the relationship between workload, power consumption, heat generation, and cooling demand
4. Trains a model to predict cooling/water requirements directly from operating conditions

## Dataset

[TU Wien data center telemetry dataset](datasets/) — server-level sensor readings including CPU load, power draw, inlet/CPU temperatures, fan speeds, network throughput, RAM usage, and running VM count.

- **2,748,525 rows × 18 columns**, multiple servers (`Series`) over time
- Raw and cleaned/engineered versions both tracked in `datasets/`

## What's Done So Far

### 1. Data Profiling & Cleaning
- Full profiling pipeline: shape, dtypes, missing values, duplicates, cardinality, categorical breakdowns
- Missing values handled; datatypes standardized (`Time` → datetime, `Series` → string)
- Investigated `CPU_cores_used` values exceeding `CPU_cores` — retained rather than dropped, since the metric doesn't map 1:1 to physical core count

### 2. Exploratory Data Analysis
- **Time-variate analysis** — power consumption over time and by day of week
- **Univariate analysis** — distribution and outlier inspection across all numeric features
- **Series-level analysis** — average power by server
- **Relationship analysis** — correlation heatmap and grouped system relationships

**Key findings:**
- Power draw is not constant — it varies over time and by day of week
- `Network_RX`/`Network_TX` are highly right-skewed relative to other features
- `CPU_Load` and `Power` are strongly positively correlated; `CPU1_Temperature` and `CPU2_Temperature` are strongly correlated with each other
- All four fan-speed variables are extremely highly correlated with each other — signaling redundancy worth handling before modeling
- Boxplots show extreme values in several variables, flagged for investigation rather than automatic removal

### 3. Feature Engineering
Engineered four groups of features on top of the raw telemetry:

| Group | Features |
|---|---|
| **Workload** | CPU core utilization (%), RAM utilization (%), derived from raw usage/total ratios |
| **Thermal** | Temperature rise (avg CPU temp − inlet temp) |
| **Cooling** | Fan-speed–derived cooling indicators |
| **Energy** | Power per CPU core — normalizes power draw against available CPU capacity |

Cleaned and engineered datasets are saved as intermediate artifacts (`datasets/`) so each stage is reproducible independently.

### 4. Physics-Based Cooling & Water-Demand Modeling
Since no direct water-consumption measurements exist in the data, cooling and water requirements are estimated from first principles:

- **Heat load** — IT power consumption (W → kW) is treated as a proxy for heat generated by the equipment
- **Cooling-water flow** — derived from heat load using water's specific heat capacity, calculated across **three cooling scenarios** (allowable temperature rise ΔT of 3°C, 5°C, and 10°C)
- **Evaporative water requirement** — derived from heat load using the latent heat of vaporization of water (≈2441.7 kJ/kg at 25°C)

As expected from the underlying thermodynamics, power, heat load, cooling-water flow, and evaporative water requirement all show a strong linear relationship with each other — this establishes the physical basis the predictive model will build on.
